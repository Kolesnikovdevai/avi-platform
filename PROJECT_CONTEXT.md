# Контекст проекта

Версия 0.1 от 03.11.2026. Источник продуктовых решений — запрос владельца проекта и предоставленный фрагмент обсуждения. Это не источник технических сведений об API Авито.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Продукт | SaaS аналитики Авито; рабочее название AvitoPulse |
| Старт | Закрытая бета с первым заказчиком и приглашёнными специалистами |
| Аудитория | Бизнес, авитологи, агентства |
| Tenant | Организация; пользователь может состоять в нескольких |
| Архитектура | Модульный монолит |
| Web | Next.js и TypeScript |
| Backend / данные | FastAPI, Python, PostgreSQL |
| Уведомления | Telegram через aiogram |
| MVP | Приглашения, роли, организации, аккаунты Авито, доступные статистика и расходы, CPL, веб-кабинет |
| Позднее | MAX, AI, подписки, расширенные отчёты и автоматизация |
| Финансовые изменения | Пополнение, переводы, управление авансом исключены из беты |

Цель — дать пользователю понятную картину расходов и обращений и вовремя сообщать о проблемах. Число функций не является критерием успеха первой версии.

## Базовые решения для проектирования

Эти решения конкретизируют исходный запрос и могут быть пересмотрены через ADR до реализации соответствующего модуля:

- Организацию создаёт оператор беты, назначая владельца; самостоятельная публичная регистрация отсутствует.
- Пользователи входят по подтверждённому email и паролю; создание учётной записи и членства возможно только по приглашению. Почтовый провайдер выбирается перед реализацией приглашений.
- Owner управляет организацией и участниками; admin — интеграциями и аналитикой; analyst — аналитикой и своими уведомлениями. В бете все участники организации видят все её аккаунты. Если клиентам агентства нужна изоляция, создаются отдельные организации.
- Один внешний аккаунт Авито принадлежит одной организации AvitoPulse. Общий доступ к одному подключению из нескольких организаций не поддерживается; перенос — отдельная контролируемая процедура с повторной авторизацией.
- Автоматический сбор — polling, если официальный API разрешает нужный режим. Webhook не считается доступным по умолчанию.
- Рабочие процессы запускаются из одного backend-проекта; начальная очередь задач и outbox — PostgreSQL.
- Интерфейс на русском. Начальное представление времени — Europe/Moscow, но отчётный день определяется подтверждённой семантикой источника; преобразование дат не должно искажать статистику.

## Что пока неизвестно

Нужны результаты AVITO_API_RESEARCH.md: схема авторизации стороннего SaaS, согласование приложения, доступные аккаунтам методы, права, ограничения, история, детализация расходов и определение обращений. Не подтверждены sandbox, webhooks, OAuth refresh и какие-либо финансовые операции.

До беты владелец определяет число организаций/аккаунтов, доступные тарифы Авито для проверки, инфраструктуру и регион размещения, политику хранения и удаления, условия работы с пользовательскими данными и оператора поддержки. Юридические документы и применимые требования должны проверяться отдельно; этот комплект не является юридическим заключением.

## Источники истины

- PRD.md — продуктовое поведение и критерии приёмки.
- AVITO_API_RESEARCH.md — доказательства внешних возможностей.
- ARCHITECTURE.md и DATABASE_DESIGN.md — технические инварианты.
- ROADMAP.md — порядок реализации и условия запуска.
- AGENTS.md — обязательные правила работы.
- docs/DESIGN_SYSTEM.md — визуальные правила по референсам владельца от 03.11.2026; реализация использует тёмную тему и утверждённую исходную палитру. Производные оттенки и семантические цвета зафиксированы явно.

При конфликте не угадывать: зафиксировать вопрос, принять решение с владельцем для изменения продуктового объёма и обновить все затронутые документы. Требования безопасности не отменяются неявно.
