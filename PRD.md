# PRD: закрытая бета AvitoPulse

Статус: проект требований. Реальная аналитика зависит от этапа проверки API; неподтверждённые показатели не являются обещанием продукта.

## Пользователи и задачи

| Пользователь | Основная задача |
|---|---|
| Владелец бизнеса | Понимать расходы и стоимость обращения по своим объявлениям |
| Авитолог | Сравнивать аккаунты и периоды, замечать отклонения |
| Агентство | Разделять клиентские данные по организациям и управлять сотрудниками |

Главный сценарий: приглашённый пользователь входит, выбирает организацию, подключает разрешённый аккаунт, получает подтверждённые данные и видит расходы, обращения и CPL с датой обновления. Затем настраивает личные Telegram-уведомления.

## Объём и приёмка

| Код | Требование | Критерий приёмки |
|---|---|---|
| F01 | Вход по приглашению | Публичная регистрация закрыта; приглашение имеет срок, одноразовое принятие, отзыв и привязку к подтверждённому email; одновременное принятие не создаёт дубликаты |
| F02 | Организации и роли | Переключение организации перепроверяет членство; owner/admin/analyst соблюдают матрицу прав; последний owner не может быть удалён без передачи роли |
| F03 | Подключение Авито | Только owner/admin; схема подтверждена исследованием; аккаунт проверен через официальный способ идентификации; секреты не попадают в UI и логи |
| F04 | Сбор статистики | Повтор синхронизации не удваивает данные; отображены время последнего успешного сбора, покрытие периода и состояние подключения |
| F05 | Расходы и CPL | Источник, состав расходов, определение обращения, валюта и период видимы; отсутствующие или несовместимые данные дают «нет данных», а не 0 |
| F06 | Веб-кабинет | Выбор организации, аккаунта, периода; таблица объявлений и сводка; отдельные состояния загрузки, пустоты, частичных данных и ошибки |
| F07 | Telegram | Одноразовая безопасная привязка личного чата; настраиваемые правила; лимит частоты; отзыв доступа прекращает отправку |
| F08 | Управление доступом | Удалённый участник теряет доступ при следующем запросе и не получает отложенные уведомления; отключённый аккаунт перестаёт синхронизироваться |
| F09 | Эксплуатация | Оператор видит ошибки сбора без секретов; аудит изменений доступа; проверено восстановление резервной копии |

## Роли

| Действие | Owner | Admin | Analyst |
|---|---|---|---|
| Просмотр всех аккаунтов организации | Да | Да | Да |
| Подключение/отключение Авито, ручной сбор | Да | Да | Нет |
| Свои Telegram-привязки и правила | Да | Да | Да |
| Приглашения, отзыв участников, смена ролей | Да | Нет | Нет |
| Настройки организации, передача владения | Да | Нет | Нет |

Оператор беты создаёт организацию отдельным контролируемым процессом. У него нет автоматического права просмотра клиентской аналитики. Режим скрытого входа от имени клиента не реализуется.

## Семантика метрик

«Лид» в интерфейсе означает только явно выбранный и подтверждённый показатель обращений источника. Это не доказательство уникального человека, сделки или продажи. Нельзя произвольно складывать звонки, контакты и сообщения без доказанной совместимости и устранения пересечений.

`CPL = сумма допустимых расходов / число допустимых обращений`.

Числитель и знаменатель должны иметь одинаковые аккаунт, гранулярность, интервал, валюту и версию определения. Состав расходов (продвижение, размещение, тариф и т. п.) фиксируется после исследования. Общие расходы аккаунта не распределяются по объявлениям без отдельной утверждённой методики.

- При 0 обращений CPL = NULL, показ «—, обращений нет»; при неизвестном числе — «нет данных».
- При подтверждённых 0 расходов и положительных обращениях CPL = 0.
- При неполном периоде CPL не выдаётся как полный: по умолчанию «нет данных за весь период», допускается отдельно подписанный расчёт по покрытой части.
- Общий CPL = сумма расходов / сумма обращений, не среднее CPL объявлений.
- Пример: 12 000 ₽ и 40 обращений → 300 ₽. Для второго набора 3 000 ₽ и 10 обращений общий CPL = 15 000 / 50 = 300 ₽.
- Округление только при показе; исходные деньги хранятся точно. Возвраты и корректировки не отбрасываются без подтверждённой методики.

Баланс — снимок на момент времени, не расход и не выручка. Показывается только при подтверждении API, отдельно от расчёта CPL. Если методы расходов и обращений несовместимы, соответствующий экран блокируется до продуктового решения.

## Синхронизация и уведомления

Состояния подключения: pending, active, reauth_required, suspended, disconnected. У успешного подключения отдельно показываются queued/running/succeeded/partial/failed состояния сборов. Недоступность данных не удаляет предыдущую успешную статистику.

Минимальные правила: ошибка/устаревание сбора, превышение выбранного порога расходов или CPL за закрытый отчётный день. CPL-правило требует минимального числа обращений и полного покрытия. Порог и окно задаёт пользователь. Для незавершённого дня финансовые пороги в бете не оцениваются.

У уведомления есть ключ дедупликации: организация, правило, аккаунт, период, версия условия. Cooldown ограничивает частоту. Повтор внешней отправки при неоднозначном результате может дать дубликат; обещание exactly-once отсутствует. Telegram-сообщение содержит минимум данных и ссылку в кабинет с повторной авторизацией.

## Качество и безопасность

Обязательны тесты доступа между двумя организациями, корректности метрик, повторов синхронизации и отзыва полномочий. Непроверенные демоданные визуально отделены от реальных. Внешняя недоступность приводит к понятному статусу, а не к ложным значениям.

Предварительные внутренние цели, а не SLA: 95% запросов кабинета к уже загруженным данным быстрее 2 секунд; уведомления об обработанном событии в пределах 5 минут при доступном Telegram. Частота сбора назначается только после проверки лимитов. До нагрузочного теста зафиксировать объём беты и сценарий; результаты сохранять с этим объёмом.

## Вне беты

MAX, AI-рекомендации, публичная регистрация, биллинг/подписки, платежи и управление авансом, изменение продвижения, массовое редактирование объявлений, CRM и расширенные PDF/Excel-отчёты. Не допускается обход API через скрытый парсинг или использование аккаунта без согласия владельца.

## Оценка результата

В бете измеряем успешность подключения, долю успешных сборов, свежесть и покрытие, расхождения с кабинетом Авито, доставку уведомлений и повторное использование кабинета. Целевые продуктовые значения согласуются после первых разрешённых проверок; качество данных и отсутствие утечек — обязательные условия продолжения.
