# AvitoPulse — стартовый комплект закрытой беты

Статус: каркас этапа 1 и локальный дизайн-прототип. Версия 0.2, 3 ноября 2026 года.

AvitoPulse — SaaS для бизнеса, авитологов и агентств: статистика собственных подключённых аккаунтов Авито, расходы, CPL и Telegram-уведомления в одном веб-кабинете. Название рабочее; связь с Авито или одобрение со стороны Авито не заявляются.

В каталоге есть Next.js интерфейс, FastAPI backend, входы worker/aiogram, Alembic и конфигурация локального PostgreSQL/CI. Это каркас, ещё не готовый к клиентам. Авторизация, tenant-таблицы, реальные подключения и отправки не реализованы. Ожидаемые возможности Авито остаются гипотезами.

Начальная задача для Codex:

Отчитывайся об изменениях, проверках и блокирующих вопросах. Не выполняй платных действий, публикацию или изменения реального аккаунта без отдельного поручения.

## Локальный запуск

Требуются Node 24, pnpm 11.25.0, uv 0.13.7/Python 3.12 и для полного окружения работающий Docker Engine. Закреплённые версии — в lock-файлах и [описании зависимостей](docs/DEPENDENCIES.md).

Только интерфейс, без БД и секретов:

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

Открыть http://127.0.0.1:3000. Все числа синтетические, период и разделы переключаются локально. CPL в браузере не рассчитывается. Остановка — Ctrl+C.

Backend без БД (из каталога `backend`):

```powershell
uv sync --frozen
uv run --frozen avitopulse-api
```

`http://127.0.0.1:8000/api/health/live` → 200; `/api/health/ready` → 503 до настройки БД и миграций. `/api/openapi.json` содержит только технический контракт.

Полное локальное окружение на Windows (из корня):

```powershell
./scripts/dev.ps1
```

Скрипт генерирует `.env` со случайными локальными паролями без вывода значений, поднимает PostgreSQL, устанавливает зависимости из lock, применяет миграции, запускает API и web. Можно передать `-Uv` с путём к uv. Существующий `.env` не перезаписывается. API останавливается вместе со скриптом; БД остаётся в локальном томе. Порты 3000/8000 должны быть свободны.

Docker Engine в текущем сеансе не отвечает: запуск этим скриптом целиком пока не подтверждён. Независимые web/API проверки выполнялись отдельно. Не пересоздавать том ради смены паролей: bootstrap ролей работает только на пустом томе.

Эквивалентные команды для БД и миграций:

```powershell
node scripts/init-local.mjs
docker compose up -d --wait db
cd backend
uv sync --frozen
uv run --frozen --env-file ../.env alembic upgrade head
uv run --frozen --env-file ../.env avitopulse-api
```

PostgreSQL опубликован только на `127.0.0.1:55432`. Runtime и миграционная роли разделены; superuser применяется только локальным bootstrap. Для остановки БД — `docker compose down` из корня; данные тома сохраняются. `.env.example` содержит только заглушки; реальные токены Авито/Telegram для каркаса не требуются.

## Проверки

```powershell
pnpm lint
pnpm typecheck
pnpm format:check
pnpm build
pnpm --filter @avitopulse/web exec playwright install chromium
pnpm test:e2e
pnpm audit --audit-level=low
```

Из `backend`:

```powershell
uv run --frozen ruff check .
uv run --frozen ruff format --check .
uv run --frozen mypy
uv run --frozen pytest
uv run --frozen avitopulse-worker --check
uv run --frozen avitopulse-bot --check
uv run --frozen pip-audit --local --skip-editable
```

Без `AVITOPULSE_TEST_DATABASE_URL` тест PostgreSQL явно пропускается. После применения миграций использовать `uv run --frozen --env-file ../.env pytest`. SQLite не используется. Worker/бот сейчас только проверяют загрузку процесса и завершаются, без задач/polling/сообщений.

Дополнительная Windows-проверка на переносимом PostgreSQL: `./scripts/check-postgres.ps1 -PgBin <путь-к-bin-PostgreSQL-18>`. Она создаёт отдельный временный кластер на `127.0.0.1:55433`, выполняет тот же bootstrap, дважды `upgrade head`, тесты и останавливает сервер. Бинарники должны быть заранее получены из [официального источника](https://www.postgresql.org/download/windows/); скрипт их не загружает и службу Windows не устанавливает. Для кириллического пути проекта используется временный ASCII junction. Тестовые данные остаются во временном каталоге; файл начального пароля удаляется.

CI: `.github/workflows/ci.yml` проверяет web/backend, реальный PostgreSQL, секреты Gitleaks и уязвимости. Проект подключён к [Kolesnikovdevai/avi-platform](https://github.com/Kolesnikovdevai/avi-platform), основная ветка — main. Изменения проходят через тематические ветки и pull requests по [Git-процессу](docs/GIT_WORKFLOW.md). Актуальная дизайн-система — светлая версия 2.0 с Inter; тёмная версия сохранена в истории.

## Планируемый стек и инструменты

Next.js / TypeScript, FastAPI / Python, PostgreSQL, aiogram. Модульный монолит с отдельными процессами API, фонового worker и Telegram-бота из одного backend-проекта. Микросервисы, Kubernetes и отдельный брокер не являются требованиями беты.

При создании каркаса выбрать совместимые поддерживаемые версии и закрепить их в lock-файлах. Планируемые средства: uv, pnpm, Alembic, SQLAlchemy, pytest, Ruff, TypeScript typecheck, ESLint, Playwright. Команды запуска и CI добавить после появления реальных конфигураций; не описывать несуществующие команды как работающие.

## Границы первой версии

Приглашения, организации и роли, подключение аккаунтов, доступные статистика и расходы, воспроизводимый CPL, Telegram-уведомления и веб-аналитика. MAX, AI, подписки, автоматизация продвижения, пополнения и управление авансом отложены. Баланс возможен только как отдельно подтверждённый показатель чтения.

До приглашения клиентов обязательны проверки разделения данных, сценариев отзыва доступа, восстановления резервной копии и достоверности расчётов. Полный перечень условий — в ROADMAP.md.
