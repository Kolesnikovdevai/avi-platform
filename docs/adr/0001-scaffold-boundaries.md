# ADR 0001: локальный каркас без tenant-данных

Дата: 03.11.2026. Статус: принято в пределах разрешённого этапа 1.

## Контекст и решение

Исходные документы задают модульный монолит Next.js/FastAPI с PostgreSQL и отдельными процессами worker/aiogram. Gate исследования не пройден. Каркас запускается независимо от интеграции.

Backend пока публикует только технические health и OpenAPI. Tenant-маршрутов нет. Начальная Alembic-миграция создаёт namespace app и минимальные права runtime; tenant-таблиц нет. Следующий этап добавит RLS и составные FK одновременно с каждой tenant-таблицей. Нельзя предоставлять данные до реализации проверяемых сессий/членства.

Миграции выполняет avitopulse_migrator. Все процессы приложения будут использовать avitopulse_runtime без владения таблицами, superuser/BYPASSRLS и членства в миграционной роли. Сейчас worker и бот имеют только одноразовую команду --check; сети, задач и отправок нет. Разделение дополнительных прав worker/бота вводится при появлении сценариев.

Readiness требует PostgreSQL, безопасную runtime-роль и baseline-ревизию. Без БД liveness работает, readiness возвращает 503. Это не проверка готовности к клиентам. Разрешены только окружения development/test; production-конфигурация требует последующего отдельного решения и развёртывания.

UI — локальная демонстрация из явно маркированного статического fixture. Значения и CPL заранее подготовлены; браузер их не рассчитывает, backend/БД их не принимает. Реальный адаптер отсутствует. В production реальные расчёты и определения будут только в backend по этапам 0/3/4.

## Последствия

Отсутствие tenant-данных позволяет проверять каркас без имитации авторизации и RLS. Полная изоляция всё ещё обязательна на этапе 2. Локальный bootstrap БД отделён от миграций, не предназначен для production и выполняется только на новом локальном томе. Скрипт генерирует отдельные случайные пароли в игнорируемый .env, не печатая их. Шифрование credentials, email и сессии не объявляются реализованными.
