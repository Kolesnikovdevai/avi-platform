# План проверки интеграции

Основание: [реестр вопросов](../../AVITO_API_RESEARCH.md), [журнал](EVIDENCE_LOG.md).
Все действия ниже запланированы, а не выполнены.

| Шаг | Условия начала | Действия и результат | Условие остановки |
|---|---|---|---|
| R01: документы | Доступный официальный источник | Зафиксировать API-продукт, дату, версию, условия SaaS, права и ссылки A01–A05 | Контракт недоступен или неприменим к SaaS |
| R02: сценарий | R01, разрешение владельца аккаунта | Зафиксировать класс/тариф/категорию без персональных данных, допустимые операции чтения и период; проверить тарификацию | Нет разрешения либо операция может быть платной без отдельного поручения |
| R03: авторизация | R02, локальное хранилище секретов | Проверить документированный flow, идентификацию, срок/отзыв; сохранить только очищенные доказательства | Несовпадение аккаунта, неподтверждённая схема подключения |
| R04: чтение | R03, подтверждённый контракт методов | Минимальная выборка объявлений и один закрытый период расходов/обращений; учесть пагинацию | Неподтверждённые права, единицы или границы периода |
| R05: сверка | R04 и разрешённый доступ к кабинету | Сравнить один аккаунт, период, зону, состав расходов и определение обращений; записать расхождения | Расхождения без объяснения, несовместимые уровни агрегации |
| R06: устойчивость | R04 | Повтор чтения; локальные имитации частичных ответов, 401/403/429/5xx и timeout; план повторного сбора исправлений | Повтор удваивает данные либо потеря покрытия скрывается |
| R07: решение | R01–R06 | Заполнить матрицу доступности, ограничения и версию определения CPL; оценить gate ROADMAP | Нет расходов/совместимого знаменателя — требуется решение владельца |

Подмена state, повтор callback, истечение и отзыв роли проверяются локально при реализации flow. Ошибки и лимиты не провоцируются нагрузкой на реальный API. Refresh/PKCE/webhook проверяются только после подтверждения поддержки. Второй класс аккаунтов требует собственного разрешения и записи; результаты первого не обобщаются.

## Протокол сверки закрытого периода

Записать ссылку на контракт; псевдоним аккаунта; гранулярность; start/end и включительность границ; timezone; валюту и единицу; состав расходов; определение обращений; статус покрытия; время получения. Для каждого значения сохранить очищенный результат API, значение кабинета, разницу и объяснение. Отдельно отметить поздние изменения и дату повторной сверки.

Суммы не считать через float. Неизвестное не заменять нулём; при нулевом знаменателе CPL отсутствует. Не распределять аккаунтные расходы по объявлениям. Неполный/несовместимый набор не подтверждает CPL.

## Хранение доказательств

Каждая новая запись содержит ID вопроса, исследователя, дату, официальный источник/версию, права, класс аккаунта, ожидаемый и фактический результат, ограничения и влияние на PRD. Перед git проверить URL, заголовки, идентификаторы и свободный текст на секреты/персональные данные. Сырые ответы по умолчанию не сохранять; необходимое временное хранение допускается только в защищённой среде с заранее определённым сроком удаления.
